# Project Chrono Command-Component-System 보고서

## 읽는 순서

1. 1장에서 프로젝트 배경과 목표를 먼저 확인한다.
2. 2.1에서 Chrono가 제공하는 Command를 기능별로 분류한다.
3. 2.2에서 Command를 로버, 지형, 충돌, 데이터 출력 Component로 묶어 해석한다.
4. 2.3에서 Component가 실제 System으로 조합되는 방식을 확인한다.
5. 3장에서 학습 결과, 최종 주제 후보, 향후 계획을 연결해 읽는다.

## 문서 작성 규칙

| 항목 | 통일 규칙 |
| --- | --- |
| 파일명 | 본문 파일은 `장절번호_영문_snake_case.md` 형식으로 작성한다. |
| 제목 | 본문 파일은 최상단에 `# 장절번호 제목` 형식의 H1을 한 개 둔다. |
| 소제목 | 주요 절은 `## 장절번호.하위번호 제목` 형식으로 작성하고, H3는 설명형 소제목으로 사용한다. |
| 이미지 | 핵심 시각자료는 대체 텍스트와 상대 경로를 갖는 표준 Markdown 이미지 문법을 사용한다. |
| 캡션 | 단일 핵심 그림은 이미지 바로 아래에 `*그림 장절-번호. 설명*` 형식의 캡션을 둔다. |
| 표 | 표 구분선은 `| --- | --- |`처럼 공백을 포함한 GitHub Markdown 형식으로 통일한다. |
| 코드 | 실행 예시는 언어가 드러나는 fenced code block으로 작성한다. |

## 시각자료 관리

보고서 본문 이미지는 각 장의 `images/` 폴더에 보관한다. Mermaid 원본과 렌더링 PNG는 함께 유지하여 구조도를 다시 생성할 수 있게 하고, 렌더 이미지와 그래프는 해당 Component 또는 System 문서에서 산출물 의미를 설명한다.
