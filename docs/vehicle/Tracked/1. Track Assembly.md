Project Chrono에서 **Track Assembly**는 차량의 한쪽 궤도 전체(스프로킷, 아이들러, 보기륜, 궤도 마디)를 하나로 묶어 관리하는 '컨테이너' 역할을 합니다.

아래 4가지의 하위 모델은 "궤도 마디(Track Shoe)들이 서로 어떻게 연결되어 있는가?"와 "궤도 자체가 어떤 물리적 성질을 갖는가?"에 따라 구분됩니다.

| **모델명**          | **연결 방식**    | **물리적 복잡도** | **실제 사례**          |
| ---------------- | ------------ | ----------- | ------------------ |
| **Single Pin**   | 1개 핀 (회전 관절) | 낮음 (빠름)     | 구형 탱크, 건설 장비       |
| **Double Pin**   | 2개 핀 + 커넥터   | 중간          | 현대식 주력 전차 (K2, M1) |
| **Band Bushing** | 고무 밴드 + 부싱   | 중간          | 고무 궤도 장갑차, 농기계     |
| **Band ANCF**    | 유연체 (FEM)    | 매우 높음       | 궤도 변형 및 파손 정밀 분석   |



#### **1. ChTrackAssemblySinglePin (싱글 핀 방식)**

- **군용 지식:** 궤도 마디와 마디를 하나의 철제 핀으로 연결하는 방식입니다. 구형 전차나 소형 궤도 차량에서 주로 볼 수 있습니다.
    
- **물리 특성:** 마디 사이의 연결 부위가 단순한 회전 관절(Revolute Joint)로 작동합니다.
    
- **특징:**
    
    - 구조가 단순하여 계산 속도가 가장 빠릅니다.
        
    - 마디 사이의 비틀림이나 복잡한 탄성을 무시하는 경우가 많습니다.
        
- **추천 용도:** 대규모 시뮬레이션이나 빠른 결과 확인이 필요할 때.

- **불러올 경우** #include <ChTrackAssemblySinglePin.h>

#### **2. ChTrackAssemblyDoublePin (더블 핀 방식)**

- **군용 지식:** 마디와 마디 사이에 별도의 '커넥터(Connector)'가 있고, 핀이 두 개 들어가는 방식입니다. (현대적인 K2 흑표, M1 에이브람스 등이 채택)
    
- **물리 특성:** 마디-핀-커넥터-핀-마디 순으로 연결되어, 싱글 핀보다 더 유연하고 충격 흡수력이 좋습니다.
    
- **특징:**
    
    - 실제 전차의 궤도 움직임과 가장 유사합니다.
        
    - 부품 수가 두 배로 늘어나므로 시뮬레이션 계산 부하가 증가합니다.
        
- **추천 용도:** 정밀한 기동 성능 분석 및 현대적 전차 모델링.
    
- **불러올 경우**: #include <ChTrackAssemblyDoublePin.h>

#### **3. ChTrackAssemblyBandBushing (부싱 기반 밴드 방식)**

- **군용 지식:** 개별 마디가 핀으로 연결된 것이 아니라, 고무나 복합소재로 된 **'연속적인 벨트(Band)'** 형태를 가집니다. 최신 장갑차나 농기계에서 쓰이는 고무 궤도와 유사합니다.
    
- **물리 특성:** 마디 사이의 연결을 '부싱(Bushing)' 요소로 처리하여, 상하좌우 모든 방향으로 미세한 변형과 감쇠(Damping)가 가능하게 모델링합니다.
    
- **특징:**
    
    - 금속 마디 간의 충돌 소음이 적고 진동이 흡수되는 특성을 시뮬레이션할 수 있습니다.
        
- **추천 용도:** 고무 궤도 차량이나 궤도의 진동/소음 분석.
    
- **불러올 경우**: #include <ChTrackAssemblyDoublePin.h>

#### **4. ChTrackAssemblyBandANCF (ANCF 유연 밴드 방식)**

- **군용 지식:** 매우 유연하고 얇은 고무 벨트형 궤도입니다.
    
- **물리 특성:** ANCF(Absolute Nodal Coordinate Formulation)라는 유한요소법(FEM) 기술을 사용합니다. 궤도 자체를 딱딱한 강체가 아닌, '출렁거리는 유연체'로 계산합니다.
    
- **특징:**
    
    - 궤도가 고속으로 회전할 때 발생하는 파동이나 원심력에 의한 변형을 가장 정확하게 묘사합니다.
        
    - 4가지 모델 중 계산량이 가장 압도적으로 많습니다.
        
- **추천 용도:** 궤도 자체의 파손, 극심한 변형, 고속 회전 시의 동역학적 특성 연구.
- **불러올 경우**: #include <ChTrackAssemblyBandANCF.h>

### **명령어 및 구현 가이드**

Track Assembly 문서를 작성하실 때 아래와 같은 흐름을 포함하면 좋습니다.

1. **초기화 (`Initialize`)**:
    
    - `vehicle.Initialize()` 호출 시 내부적으로 `TrackAssembly`가 생성됩니다.
        
    - 이때 스프로킷 위치, 아이들러 위치, 보기륜의 개수 등을 설정 파일(JSON)이나 코드로 정의합니다.
        
2. **구성 요소 접근 (`Get components`)**:
    
    - `GetSprocket()`, `GetIdler()`, `GetTrackShoe(n)` 등의 함수를 통해 전체 조립체 내부의 개별 부품 객체에 접근할 수 있습니다.
        
3. **상태 모니터링**:
    
    - `GetTrackTension()`: 현재 궤도에 걸리는 장력을 확인합니다. (궤도가 벗겨지는 '탈궤' 현상을 분석할 때 필수)
        

**Tip:** Obsidian에 적으실 때, "속도가 중요하다면 Single Pin, 실제 전차와 똑같이 만들고 싶다면 Double Pin, 고무 궤도라면 Band 방식을 선택하세요"라고 가이드를 주면 지식이 부족한 팀원들도 쉽게 이해할 수 있을 것입니다.
