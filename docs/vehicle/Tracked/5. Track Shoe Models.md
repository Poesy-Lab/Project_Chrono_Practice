# Chrono Vehicle – Tracked Vehicle / Track Shoe Models

## 1. Track Shoe란?

`Track shoe`는 tracked vehicle에서 **궤도(track)를 구성하는 기본 단위**이다. 일반 차량에서 타이어가 지면과 직접 접촉하는 부품이라면, 궤도 차량에서는 수십 개의 track shoe가 연결되어 하나의 track assembly를 이루고, 이 track shoe들이 지면, sprocket, idler, road wheel과 접촉한다.

Chrono::Vehicle 문서에 따르면 track shoe template은 크게 다음 네 가지로 나뉜다.

| 분류                      | 의미                                                            |
| ----------------------- | ------------------------------------------------------------- |
| Single-pin track shoe   | 하나의 shoe body가 이웃 shoe와 revolute joint로 연결되는 segmented track  |
| Double-pin track shoe   | main track pad body와 두 개의 connector body를 가지는 segmented track |
| Band-bushing track shoe | rigid tread + bushing 기반 web을 사용하는 continuous-band track      |
| Band-ANCF track shoe    | rigid tread + ANCF shell 기반 web을 사용하는 continuous-band track   |

Chrono 문서에서는 single-pin과 double-pin track shoe template이 모두 **central guiding pin** 또는 **lateral guiding pin**을 가질 수 있다고 설명한다. 또한 각 track shoe template은 치수, 질량, 관성, 접촉 형상 등으로 완전히 parameterized되어 있다.

---

## 2. Chrono에서 Track Shoe의 역할

Track shoe는 단순한 시각적 궤도 조각이 아니라, tracked vehicle simulation에서 여러 물리적 역할을 동시에 가진다.

|역할|설명|
|---|---|
|지면 접촉|terrain과 직접 접촉하여 차량 하중과 traction을 전달|
|sprocket과 맞물림|sprocket gear와 접촉하여 구동력을 전달받음|
|idler / road wheel / roller와 접촉|track path를 유지하고 차체 하중을 지지|
|track tension 전달|이웃 shoe 또는 band web을 통해 장력 전달|
|track assembly 구성|여러 track shoe가 연결되어 한쪽 track 전체를 형성|

구조적으로 보면 다음과 같다.

> Driveline  
> → Sprocket  
> → Track shoe  
> → Ground contact  
> → Vehicle motion

또는 track assembly 관점에서는 다음과 같다.

> TrackAssembly  
> → 여러 개의 TrackShoe  
> → 이웃 shoe와 연결  
> → sprocket / idler / road wheel과 접촉  
> → terrain과 접촉

---

## 3. Track Shoe의 전체 분류 구조

Chrono의 tracked shoe model은 다음처럼 이해하면 된다.

> Track Shoe Models  
> ├─ Segmented Track Shoe  
> │　├─ Single-pin Track Shoe  
> │　└─ Double-pin Track Shoe  
> │  
> └─ Continuous Band Track Shoe  
> 　　├─ Band-bushing Track Shoe  
> 　　└─ Band-ANCF Track Shoe

여기서 중요한 차이는 **segmented track**과 **continuous band track**이다.

|구분|설명|
|---|---|
|Segmented track|여러 개의 rigid shoe가 joint로 연결된 궤도|
|Continuous band track|고무 벨트처럼 연속적인 web이 있고, 그 위에 rigid tread가 붙은 궤도|

M113 모델에서도 이 네 가지 계열을 모두 제공한다. M113 vehicle에는 `M113_Vehicle_SinglePin`, `M113_Vehicle_DoublePin`, `M113_Vehicle_BandBushing`, `M113_Vehicle_BandANCF`가 존재한다.

# 4. 공통 Base Class: `ChTrackShoe`

## 4.1 개념

`ChTrackShoe`는 모든 track shoe의 공통 base class이다. 이 클래스는 track shoe가 공통적으로 가져야 하는 기능을 정의한다.

대표적인 공통 기능은 다음과 같다.

|함수|의미|
|---|---|
|`GetType()`|guide pin type 반환|
|`GetIndex()`|track assembly 안에서 이 shoe의 index 반환|
|`GetShoeBody()`|shoe body 반환|
|`GetTension()`|해당 shoe에서의 track tension 반환|
|`GetHeight()`|track shoe 높이 반환|
|`GetPitch()`|track shoe pitch length 반환|
|`GetGroundContactGeometry()`|terrain과 접촉하는 contact geometry 반환|
|`EnableCollision(bool val)`|shoe body collision 활성/비활성화|
|`Initialize()`|track shoe subsystem 초기화|
|`SetIndex()`|track assembly 내부 index 설정|

공식 API에 따르면 `GetType()`은 guide pin type을 반환하며, 이 type은 같은 track assembly 안의 idler와 road wheel과 일관되어야 한다.

---

## 4.2 `GetPitch()`의 중요성

`GetPitch()`는 track shoe 하나의 pitch length를 반환한다. M113 single-pin API 문서에서는 이 pitch가 **sprocket gear pitch와 일치해야 한다**고 설명한다.

즉, track shoe pitch는 단순 치수가 아니라 다음 항목들과 직접 연결된다.

|관련 항목|이유|
|---|---|
|Sprocket tooth spacing|sprocket과 track shoe가 제대로 맞물려야 함|
|Track assembly 전체 길이|shoe 개수 × pitch가 track 길이에 영향|
|Idler tensioner 설정|track 길이가 바뀌면 장력 조건도 바뀜|
|Slip 계산|sprocket 회전과 track 진행 거리 관계에 영향|

따라서 M113 모델을 수정할 때 track shoe pitch를 바꾸면, sprocket profile과 track assembly 설정도 함께 확인해야 한다.

---

## 4.3 `GetType()`의 중요성

`GetType()`은 track shoe의 guide pin 구조를 나타낸다. Chrono 문서에서는 single-pin track shoe가 `CENTRAL_PIN` 또는 `LATERAL_PIN` type이 될 수 있다고 설명한다.

이 값은 다음 부품들과 호환되어야 한다.

|부품|관련성|
|---|---|
|Idler wheel|central guide 또는 lateral guide에 맞는 wheel 필요|
|Road wheel|track shoe guide pin 구조와 wheel geometry가 맞아야 함|
|Roller|track path 유지에 영향|
|Sprocket|lateral contact 및 sprocket-track engagement에 영향|

정리하면:

> Track shoe의 guide pin type  
> → Idler / road wheel / roller type과 일치해야 함  
> → 일치하지 않으면 접촉 또는 track guiding이 비정상적으로 작동할 수 있음

---

# 5. Single-pin Track Shoe

## 5.1 개념

`Single-pin track shoe`는 하나의 rigid body로 구성된 track shoe이다. 이 shoe body는 이웃 track shoe들과 **revolute joint**로 연결된다. 공식 문서에서는 single-pin track shoe가 single body와 non-trivial contact geometry를 가지며, 이웃 shoe와 revolute joint로 연결된다고 설명한다.

기본 클래스는 다음과 같다.

|클래스|설명|
|---|---|
|`chrono::vehicle::ChTrackShoeSinglePin`|single-pin track shoe의 base class|
|`chrono::vehicle::TrackShoeSinglePin`|JSON/template 기반 single-pin track shoe|
|`chrono::vehicle::m113::M113_TrackShoeSinglePin`|M113용 single-pin track shoe|

---

## 5.2 구조

Single-pin track shoe의 구조는 비교적 단순하다.

> Shoe body  
> → 앞쪽 revolute joint  
> → 앞쪽 neighbor shoe  
> → 뒤쪽 revolute joint  
> → 뒤쪽 neighbor shoe

Chrono 관점에서는 하나의 shoe body가 있고, 이 body가 이웃 shoe와 pin joint로 연결되어 궤도를 형성한다.

---

## 5.3 주요 함수

|함수|의미|
|---|---|
|`GetTension()`|이 track shoe에서의 장력 반환|
|`Construct()`|track shoe subsystem 생성 및 초기화|
|`GetShoeMass()`|shoe body 질량 반환|
|`GetShoeInertia()`|shoe body 관성 반환|
|`GetFrontCylinderLoc()`|앞쪽 contact cylinder 위치 반환|
|`GetRearCylinderLoc()`|뒤쪽 contact cylinder 위치 반환|
|`GetCylinderRadius()`|contact cylinder 반지름 반환|
|`GetLateralContactPoint()`|sprocket lateral contact point 반환|
|`GetGroundContactGeometry()`|지면 접촉 형상 반환|

`ChTrackShoeSinglePin::GetTension()`은 해당 track shoe의 연결에서 발생하는 힘을 shoe reference frame 기준으로 반환한다.

---

## 5.4 Contact cylinder의 의미

Single-pin track shoe에는 `GetFrontCylinderLoc()`, `GetRearCylinderLoc()`, `GetCylinderRadius()`가 있다. API 문서에 따르면 front contact cylinder 위치는 shoe reference frame에서 양의 x 방향, rear contact cylinder 위치는 음의 x 방향 기준으로 정의된다.

이는 sprocket이나 track wheel과 접촉할 때 사용할 단순화된 접촉 형상으로 이해할 수 있다.

|함수|의미|
|---|---|
|`GetFrontCylinderLoc()`|shoe 앞쪽 접촉 cylinder 위치|
|`GetRearCylinderLoc()`|shoe 뒤쪽 접촉 cylinder 위치|
|`GetCylinderRadius()`|접촉 cylinder 반지름|

---

## 5.5 M113 Single-pin Track Shoe

M113 모델에서는 다음 클래스가 제공된다.

|클래스|설명|
|---|---|
|`M113_TrackShoeSinglePin`|M113 vehicle용 single-pin track shoe subsystem|

공식 문서에서는 `M113_TrackShoeSinglePin`을 M113 vehicle의 single-pin track shoe subsystem이라고 설명한다. 이 클래스는 `GetType()`, `GetHeight()`, `GetPitch()`, `GetShoeMass()`, `GetShoeInertia()`, `GetFrontCylinderLoc()`, `GetRearCylinderLoc()`, `GetCylinderRadius()`, `GetLateralContactPoint()`, `GetGroundContactGeometry()` 등을 구현한다.

---

# 6. Double-pin Track Shoe

## 6.1 개념

`Double-pin track shoe`는 single-pin보다 구조가 복잡하다. 공식 문서에 따르면 double-pin track shoe template은 main track pad body 외에도 두 개의 additional connector body를 포함한다. 이 connector body들은 이웃 pad와 revolute joint로 연결되며, sprocket gear와 충돌/접촉하는 contact geometry를 가진다.

기본 클래스는 다음과 같다.

|클래스|설명|
|---|---|
|`chrono::vehicle::ChTrackShoeDoublePin`|double-pin track shoe의 base class|
|`chrono::vehicle::TrackShoeDoublePin`|JSON/template 기반 double-pin track shoe|
|`chrono::vehicle::m113::M113_TrackShoeDoublePin`|M113용 double-pin track shoe|

---

## 6.2 구조

Double-pin track shoe는 다음처럼 이해하면 된다.

> Main shoe body  
> → Left connector body  
> → Right connector body  
> → Connector와 shoe 사이 revolute joint  
> → Connector와 이웃 shoe 사이 revolute joint  
> → Sprocket과 connector contact

Single-pin이 “shoe body 하나” 중심이라면, double-pin은 **shoe body + connector bodies** 구조이다.

---

## 6.3 주요 구성요소

`ChTrackShoeDoublePin`의 protected attributes에는 다음과 같은 내부 요소가 있다.

|내부 요소|의미|
|---|---|
|`m_topology`|double-pin track shoe topology|
|`m_connector_L`|left connector body|
|`m_connector_R`|right connector body|
|`m_joint_L`|shoe와 left connector 사이 joint|
|`m_joint_R`|shoe와 right connector 사이 joint|
|`m_rsda_L`|left revolute joint의 optional RSDA|
|`m_rsda_R`|right revolute joint의 optional RSDA|
|`m_connection_joint_L`|이웃 shoe와의 left connection joint|
|`m_connection_joint_R`|이웃 shoe와의 right connection joint|
|`m_connection_rsda_L`|connection joint의 optional RSDA|
|`m_connection_rsda_R`|connection joint의 optional RSDA|

여기서 RSDA는 일반적으로 **Rotational Spring-Damper Actuator**로 이해하면 된다. 즉, joint에 회전 스프링/댐퍼 효과를 줄 수 있는 요소이다.

---

## 6.4 주요 함수

|함수|의미|
|---|---|
|`GetPitch()`|track shoe pitch length 반환|
|`GetTension()`|track shoe 장력 반환|
|`Construct()`|double-pin shoe 생성|
|`AddVisualizationAssets()`|시각화 asset 추가|
|`GetShoeMass()`|main shoe body 질량|
|`GetShoeInertia()`|main shoe body 관성|
|`GetShoeLength()`|pin 사이 shoe length|
|`GetShoeWidth()`|connector separation|
|`GetConnectorMass()`|connector body 질량|
|`GetConnectorInertia()`|connector body 관성|
|`GetConnectorLength()`|connector pin 간 거리|
|`GetConnectorWidth()`|connector width, 주로 시각화용|
|`GetConnectorRadius()`|connector body 반지름|

Double-pin API 문서에서는 `GetShoeLength()`가 pin 사이 거리, `GetShoeWidth()`가 connector 사이 간격, `GetConnectorLength()`가 connector body의 pin 사이 거리라고 설명한다.

---

## 6.5 M113 Double-pin Track Shoe

M113 모델에서는 다음 클래스가 제공된다.

|클래스|설명|
|---|---|
|`M113_TrackShoeDoublePin`|M113 vehicle용 double-pin track shoe subsystem|

M113 model 페이지에서도 `M113_TrackShoeDoublePin`이 M113 vehicle의 double-pin track shoe subsystem으로 제공된다고 정리되어 있다.

Double-pin track shoe는 single-pin보다 body와 joint 수가 많으므로, 일반적으로 simulation cost가 더 커질 수 있다. 대신 connector가 분리되어 있어 sprocket engagement와 pin/contact 구조를 더 세밀하게 표현할 수 있다.

# 7. Band Track Shoe 공통 구조

## 7.1 개념

`Band track shoe`는 segmented rigid shoe만으로 이루어진 track이 아니라, **continuous band track**을 표현하기 위한 계열이다. Chrono 문서에서는 두 종류의 continuous-band track model을 제공한다고 설명한다.

Band track 계열의 공통 base class는 다음과 같다.

|클래스|설명|
|---|---|
|`chrono::vehicle::ChTrackShoeBand`|rigid tread를 사용하는 continuous band track shoe의 base class|

공식 API에서는 `ChTrackShoeBand`를 rigid treads를 사용하는 continuous band track shoe의 base class라고 설명하며, 실제 derived class가 서로 다른 track web 모델을 지정한다고 설명한다.

---

## 7.2 Band track의 기본 구성

Band track shoe는 다음 두 요소로 생각하면 쉽다.

|요소|의미|
|---|---|
|Tread body|지면과 접촉하는 rigid tread|
|Web|tread들을 연결하는 연속적인 belt 부분|

즉:

> Rigid tread  
> → Continuous web  
> → Neighbor tread  
> → Continuous band track 형성

Segmented track이 joint로 연결된 rigid link chain에 가깝다면, band track은 deformable 또는 compliant한 web이 있는 연속 벨트 구조에 가깝다.

---

## 7.3 Band track 공통 주요 함수

|함수|의미|
|---|---|
|`GetPitch()`|band track shoe pitch 반환|
|`Construct()`|band track shoe 생성|
|`Connect()`|이웃 track shoe와 연결|
|`WriteTreadVisualizationMesh()`|절차적으로 생성된 tread visualization mesh를 OBJ로 저장|
|`ExportTreadVisualizationMeshPovray()`|tread visualization mesh를 PovRay macro로 export|
|`GetTreadMass()`|tread body 질량|
|`GetWebMass()`|web 질량|
|`GetTreadInertia()`|tread body 관성|
|`GetWebInertia()`|web 관성|
|`GetGuideBoxDimensions()`|guide pin contact box 치수|
|`GetGuideBoxOffsetX()`|guide pin의 X 방향 offset|
|`GetBeltWidth()`|belt width|
|`GetToothTipLength()`|tread tooth tip flat length|
|`GetToothBaseLength()`|tooth base length|
|`GetToothWidth()`|tooth profile section width|
|`GetToothHeight()`|tooth 높이|
|`GetToothArcRadius()`|tooth arc radius|
|`GetWebLength()`|web 전체 길이|
|`GetWebThickness()`|web 두께|
|`GetTreadLength()`|ground contact pad 길이|
|`GetTreadThickness()`|ground contact pad 두께|
|`AddShoeContact()`|tread body contact geometry 추가|

이 함수들은 `ChTrackShoeBand` API에 정의되어 있으며, 특히 tooth geometry와 belt/web geometry를 별도로 다룬다는 점이 중요하다.

# 8. Band-bushing Track Shoe

## 8.1 개념

`Band-bushing track shoe`는 continuous band track을 **bushing-based web**으로 표현하는 모델이다. 공식 API에서는 `ChTrackShoeBandBushing`을 bushing-based web을 사용하는 continuous band track shoe의 base class라고 설명한다.

기본 클래스는 다음과 같다.

|클래스|설명|
|---|---|
|`chrono::vehicle::ChTrackShoeBandBushing`|bushing-based web을 사용하는 continuous band track shoe base class|
|`chrono::vehicle::TrackShoeBandBushing`|JSON/template 기반 band-bushing shoe|
|`chrono::vehicle::m113::M113_TrackShoeBandBushing`|M113용 band-bushing shoe|

---

## 8.2 구조

Band-bushing 모델에서는 web이 여러 segment로 나뉘고, 이 segment 사이의 탄성/감쇠 거동을 bushing으로 표현한다.

> Rigid tread  
> → Web segment  
> → Bushing stiffness/damping  
> → Next web segment  
> → Neighbor tread

즉, band 전체를 완전한 유한요소 shell로 모델링하기보다는, 여러 rigid 또는 semi-rigid segment와 bushing data를 사용해서 compliant belt 특성을 근사하는 방식으로 이해할 수 있다.

---

## 8.3 주요 함수

|함수|의미|
|---|---|
|`GetNumWebSegments()`|web section을 몇 개 segment로 나눌지 반환|
|`GetWebSegmentLength()`|하나의 web segment 길이 반환|
|`GetWebSegment(index)`|특정 web segment body 반환|
|`GetBushingData()`|bushing stiffness 및 damping data 반환|
|`AddWebContact()`|web segment body에 contact geometry 추가|

공식 API에서는 `GetNumWebSegments()`가 web section이 몇 개 segment로 나뉘는지 반환하고, `GetBushingData()`가 bushing stiffness 및 damping data를 반환한다고 설명한다.

---

## 8.4 M113 Band-bushing Track Shoe

M113 모델에서는 다음 클래스가 제공된다.

|클래스|설명|
|---|---|
|`M113_TrackShoeBandBushing`|M113 vehicle용 continuous band rigid-link track shoe subsystem|

M113 model 페이지에서는 `M113_TrackShoeBandBushing`과 `M113_TrackAssemblyBandBushing`이 제공되며, M113 vehicle에는 bushing-based continuous tracks 구성이 존재한다고 설명한다.

# 9. Band-ANCF Track Shoe

## 9.1 개념

`Band-ANCF track shoe`는 continuous band track의 web을 **ANCF shell 기반**으로 표현하는 모델이다. ANCF는 Absolute Nodal Coordinate Formulation의 약자로, 큰 변형을 가지는 flexible body를 표현할 때 사용되는 유한요소 기반 formulation이다.

공식 API에서는 `ChTrackShoeBandANCF`를 ANCF shell-based web을 사용하는 continuous band track shoe의 base class라고 설명한다.

기본 클래스는 다음과 같다.

|클래스|설명|
|---|---|
|`chrono::vehicle::ChTrackShoeBandANCF`|ANCF shell-based web을 사용하는 continuous band track shoe base class|
|`chrono::vehicle::TrackShoeBandANCF`|JSON/template 기반 band-ANCF shoe|
|`chrono::vehicle::m113::M113_TrackShoeBandANCF`|M113용 band-ANCF shoe|

---

## 9.2 구조

Band-ANCF 모델은 web을 shell element로 모델링한다.

> Rigid tread  
> → ANCF shell web  
> → Neighbor tread  
> → Flexible continuous band

Band-bushing이 bushing stiffness/damping을 사용해 web compliance를 근사한다면, Band-ANCF는 web 자체를 flexible shell mesh로 모델링하는 방식에 가깝다.

---

## 9.3 ANCF element type

`ChTrackShoeBandANCF`에는 다음 enum이 있다.

|ElementType|의미|
|---|---|
|`ANCF_4`|4-node ANCF shell element|
|`ANCF_8`|8-node ANCF shell element|

공식 API에서는 `ElementType` enum으로 `ANCF_4`와 `ANCF_8`을 제공하며, 생성자에서 element type과 curvature constraint 여부를 지정할 수 있다.

---

## 9.4 주요 함수

|함수|의미|
|---|---|
|`GetElementType()`|사용 중인 ANCF element type 반환|
|`GetNumElementsLength()`|web 길이 방향 shell element 개수|
|`GetNumElementsWidth()`|web 폭 방향 shell element 개수|
|`GetSteelLayerThickness()`|inner steel layer 두께|
|`GetTension()`|해당 track shoe에서의 장력 반환|
|`Construct()`|band-ANCF shoe 생성|
|`AddVisualizationAssets()`|시각화 asset 추가|

공식 API에서는 `GetNumElementsLength()`가 tread body 사이 web length 방향 element 개수를 반환하고, `GetNumElementsWidth()`가 side-to-side 방향 element 개수를 반환한다고 설명한다. 또한 `GetSteelLayerThickness()`는 inner steel layer 두께를 반환한다.

## 9.5 M113 Band-ANCF Track Shoe

M113 모델에서는 다음 클래스가 제공된다.

|클래스|설명|
|---|---|
|`M113_TrackShoeBandANCF`|M113 vehicle용 continuous band rigid-link track shoe subsystem|

M113 model 페이지에서는 `M113_Vehicle_BandANCF`, `M113_TrackAssemblyBandANCF`, `M113_TrackShoeBandANCF`가 제공된다고 정리되어 있다.

# 10. 네 가지 Track Shoe 모델 비교

|항목|Single-pin|Double-pin|Band-bushing|Band-ANCF|
|---|---|---|---|---|
|Track 종류|segmented|segmented|continuous band|continuous band|
|기본 구성|shoe body 하나|main shoe + connector bodies|rigid tread + bushing web|rigid tread + ANCF shell web|
|이웃 shoe 연결|revolute joint|connector + revolute joints|bushing/web segment|shell element web|
|sprocket 접촉|shoe body contact geometry|connector body contact geometry|tread tooth geometry|tread tooth geometry|
|유연성 표현|낮음|낮음~중간|bushing으로 근사|ANCF shell로 비교적 상세|

|M113 클래스|`M113_TrackShoeSinglePin`|`M113_TrackShoeDoublePin`|`M113_TrackShoeBandBushing`|`M113_TrackShoeBandANCF`|
|적합한 용도|단순 segmented track 모델|더 상세한 segmented track 모델|continuous band 근사|flexible belt 상세 모델|

# 11. M113 모델에서 Track Shoe의 위치

M113 tracked vehicle에서 track shoe는 track assembly의 핵심 구성요소이다. M113 모델에는 다음 대응 관계가 있다.

|Vehicle class|Track assembly|Track shoe|
|---|---|---|
|`M113_Vehicle_SinglePin`|`M113_TrackAssemblySinglePin`|`M113_TrackShoeSinglePin`|
|`M113_Vehicle_DoublePin`|`M113_TrackAssemblyDoublePin`|`M113_TrackShoeDoublePin`|
|`M113_Vehicle_BandBushing`|`M113_TrackAssemblyBandBushing`|`M113_TrackShoeBandBushing`|
|`M113_Vehicle_BandANCF`|`M113_TrackAssemblyBandANCF`|`M113_TrackShoeBandANCF`|

이를 구조적으로 표현하면 다음과 같다.

> M113_Vehicle  
> → TrackAssembly  
> → 여러 개의 TrackShoe  
> → Sprocket / Idler / Road wheel과 접촉  
> → Terrain과 접촉

---

# 12. Sprocket, Idler와의 관계

## 12.1 Sprocket과의 관계

Sprocket은 track shoe에 구동력을 전달한다.

|Track shoe type|대응 sprocket|
|---|---|
|Single-pin|`M113_SprocketSinglePin`|
|Double-pin|`M113_SprocketDoublePin`|
|Band track|`M113_SprocketBand`|

Sprocket 문서에서처럼, sprocket은 track shoe와의 custom contact / gear profile engagement가 중요하다. Track shoe 쪽에서는 `GetPitch()`, sprocket contact material, contact cylinder 또는 connector geometry가 중요하다.

---

## 12.2 Idler / Road wheel과의 관계

Idler와 road wheel은 track shoe를 구동하기보다는 track path를 유지하고 하중을 전달한다.

Track shoe 쪽에서 중요한 항목은 다음과 같다.

|항목|이유|
|---|---|
|`GetType()`|central/lateral guide pin type이 wheel type과 맞아야 함|
|`GetHeight()`|wheel과 track shoe의 접촉 높이에 영향|
|`GetGroundContactGeometry()`|terrain 접촉 형상|
|`GetLateralContactPoint()`|lateral guiding 및 sprocket lateral contact에 영향|
|band track의 guide box geometry|wheel과 guide pin 접촉에 영향|

---

# 13. M113 기반 프로젝트에서 어떤 모델을 선택해야 할까?

## 13.1 처음 공부하거나 빠르게 구현할 때

가장 먼저 추천할 모델은 다음이다.

|추천 모델|이유|
|---|---|
|`M113_Vehicle_SinglePin`|구조가 비교적 단순하고 이해하기 쉬움|
|`M113_TrackShoeSinglePin`|body 하나 + revolute joint 구조라 디버깅이 쉬움|

처음 Chrono tracked vehicle을 공부하는 단계에서는 single-pin이 가장 직관적이다.

---

## 13.2 실제 M113 궤도를 더 자세히 보고 싶을 때

다음 단계에서는 double-pin 모델이 유용하다.

|추천 모델|이유|
|---|---|
|`M113_Vehicle_DoublePin`|connector body까지 포함하여 sprocket engagement 구조가 더 세밀함|
|`M113_TrackShoeDoublePin`|connector mass, connector inertia, connector radius 등을 따로 정의 가능|

다만 double-pin은 body와 joint 수가 증가하기 때문에 simulation이 더 복잡해질 수 있다.

---

## 13.3 고무궤도 또는 연속 벨트 거동을 보고 싶을 때

continuous band 모델을 봐야 한다.

|추천 모델|특징|
|---|---|
|`M113_Vehicle_BandBushing`|bushing 기반 web으로 continuous band를 비교적 간단히 근사|
|`M113_Vehicle_BandANCF`|ANCF shell 기반 web으로 flexible belt 거동을 더 상세하게 표현|

캡스톤에서 계산 안정성과 구현 난이도를 고려한다면, 일반적으로는 다음 순서로 접근하는 것이 좋다.

> Single-pin  
> → Double-pin  
> → Band-bushing  
> → Band-ANCF

# 14. 수정 시 우선 확인해야 할 항목

M113 track shoe를 수정하거나 새로운 tracked vehicle에 응용할 때는 다음 항목을 우선 확인해야 한다.

|확인 항목|이유|
|---|---|
|`GetPitch()`|sprocket pitch와 반드시 맞아야 함|
|`GetType()`|idler/road wheel guide type과 맞아야 함|
|`GetHeight()`|wheel, sprocket, ground contact 위치에 영향|
|`GetShoeMass()` / `GetTreadMass()`|track 전체 질량에 큰 영향|
|`GetShoeInertia()` / `GetTreadInertia()`|track 동역학 응답에 영향|
|`GetGroundContactGeometry()`|terrain과의 접촉력 결정|
|`GetLateralContactPoint()`|lateral guiding과 detracking 방지에 영향|
|`GetSprocketContactMaterial()`|sprocket-track 접촉 물성|
|Double-pin connector geometry|sprocket engagement 및 joint 위치에 영향|
|Band web stiffness/damping|continuous belt 장력과 변형에 영향|
|ANCF element count|정확도와 계산 비용에 영향|

# 15. 주의할 점

## 15.1 Track shoe type과 sprocket type을 섞으면 안 된다

Single-pin track shoe는 single-pin sprocket과, double-pin track shoe는 double-pin sprocket과, band track shoe는 band sprocket과 함께 사용해야 한다.

잘못된 조합 예시:

|잘못된 조합|문제|
|---|---|
|`M113_TrackShoeSinglePin` + `M113_SprocketDoublePin`|sprocket engagement geometry 불일치|
|`M113_TrackShoeDoublePin` + `M113_SprocketBand`|segmented connector 구조와 band tooth 구조 불일치|
|`M113_TrackShoeBandANCF` + `M113_SprocketSinglePin`|continuous band와 single-pin sprocket 구조 불일치|

---

## 15.2 Track shoe pitch를 바꾸면 전체 track assembly가 영향을 받는다

`GetPitch()`는 sprocket gear pitch와 일치해야 한다.  
따라서 pitch를 바꾸면 다음 항목도 함께 확인해야 한다.

|함께 확인할 항목|이유|
|---|---|
|sprocket tooth pitch|맞물림 조건|
|sprocket radius / addendum radius|track 진행 거리|
|track shoe 개수|전체 track 길이|
|idler 위치|track tension|
|tensioner free length|장력 기준 길이|
|road wheel 배치|track path geometry|

---

## 15.3 Collision geometry와 visualization mesh는 다를 수 있다

Track shoe에서 실제 contact에 사용되는 geometry와 화면에 보이는 mesh는 다를 수 있다. 특히 band track 계열은 procedural tread visualization mesh를 export하는 함수가 따로 존재한다. `WriteTreadVisualizationMesh()`는 생성된 tread visualization mesh를 OBJ 파일로 저장하는 함수이고, `ExportTreadVisualizationMeshPovray()`는 PovRay용 macro로 export하는 함수이다.

따라서 CAD mesh나 visualization asset만 바꿨다고 해서 실제 접촉 거동이 바뀐다고 생각하면 안 된다.

---

## 15.4 Band-ANCF는 정확하지만 비용이 커질 수 있다

Band-ANCF는 web을 ANCF shell element로 모델링하므로, flexible belt 거동을 더 자세히 볼 수 있다. 하지만 element 개수, 폭 방향 discretization, steel layer thickness 등 더 많은 parameter가 들어간다. `GetNumElementsLength()`와 `GetNumElementsWidth()`는 각각 web 길이 방향과 폭 방향 element 개수를 정의한다.

따라서 단순 주행 시뮬레이션이나 초기 개발 단계에서는 single-pin 또는 double-pin으로 먼저 시작하고, belt flexibility가 중요한 경우에 band 계열로 넘어가는 것이 좋다.

---

# 16. 한 줄 요약

Chrono Vehicle에서 `Track Shoe`는 tracked vehicle의 **궤도를 구성하는 기본 물리 단위**이며, 지면 접촉, sprocket과의 구동력 전달, idler/road wheel과의 접촉, track tension 전달을 모두 담당한다.

Chrono는 track shoe를 네 가지 계열로 제공한다.

|모델|핵심 의미|
|---|---|
|Single-pin|가장 단순한 segmented track shoe|
|Double-pin|connector body를 포함한 더 상세한 segmented track shoe|
|Band-bushing|bushing 기반 web을 사용하는 continuous band track|
|Band-ANCF|ANCF shell 기반 web을 사용하는 flexible continuous band track|

M113 기반 프로젝트에서는 다음 순서로 접근하는 것이 가장 안전하다.

> `M113_TrackShoeSinglePin`으로 구조 이해  
> → `M113_TrackShoeDoublePin`으로 connector 기반 segmented track 이해  
> → `M113_TrackShoeBandBushing`으로 continuous band 근사 이해  
> → `M113_TrackShoeBandANCF`로 flexible web 상세 모델 이해

Track shoe를 수정할 때 가장 먼저 확인해야 할 핵심은 다음이다.

|핵심 확인 요소|의미|
|---|---|
|`GetPitch()`|sprocket pitch와 일치해야 함|
|`GetType()`|idler/road wheel guide pin 구조와 일치해야 함|
|`GetGroundContactGeometry()`|terrain 접촉 거동 결정|
|`GetLateralContactPoint()`|lateral guiding 및 sprocket lateral contact|
|mass / inertia|track 전체 동역학에 영향|
|connector 또는 web parameters|track flexibility와 계산 비용에 영향|
